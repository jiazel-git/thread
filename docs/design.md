# C++17 线程池设计文档

## 1. 概述

### 1.1 设计目标

| 目标 | 描述 |
|------|------|
| **混合线程模型** | 固定核心线程 + 动态扩展线程 |
| **优先级调度** | 任务优先级队列，支持老化机制防止饥饿 |
| **高级任务控制** | 取消、超时、批量提交、延迟执行 |
| **工作窃取** | 每线程本地队列，实现负载均衡 |
| **C++17 标准** | 使用 std::future、std::atomic、无锁模式 |

### 1.2 整体架构

```
+--------------------------------------------------------------------+
|                           线程池                                    |
+--------------------------------------------------------------------+
|                                                                     |
|  +------------+      +------------------------------------------+  |
|  |  管理线程  |      |            核心工作线程                    |  |
|  |  Manager   |----->|  [C0]  [C1]  [C2]  [C3]                  |  |
|  |            |      |   |     |     |     |                    |  |
|  | - 动态伸缩 |      |   v     v     v     v                    |  |
|  | - 负载监控 |      |  [本地工作窃取队列 (每线程, LIFO弹出)]     |  |
|  +------------+      +------------------------------------------+  |
|        |                                                             |
|        v                                                             |
|  +---------+       +------------------------------------------+    |
|  | 核心   |       |          全局优先级队列                    |    |
|  | 线程池 |       |  [关键] [高] [普通] [低] [后台]           |    |
|  +---------+       +------------------------------------------+    |
|                                                                     |
|  +--------------------------------------------------------------+  |
|  |                        任务系统                               |  |
|  |  - 状态追踪(待处理/运行中/已完成/已取消)                     |  |
|  |  - 优先级分级(5级)                                           |  |
|  |  - 延迟执行支持                                              |  |
|  |  - 回调钩子(执行前/执行后)                                   |  |
|  +--------------------------------------------------------------+  |
+--------------------------------------------------------------------+
```

## 2. 线程模型

### 2.1 混合线程管理

```
+------------------------------------------------------------+
|                     线程状态流转                             |
+------------------------------------------------------------+
|                                                            |
|   +---------+     +---------+     +-----------+            |
|   |  核心   |---->|  活跃   |---->|   空闲    |            |
|   |  线程   |     | (忙碌)  |     |  (等待中) |            |
|   +----+----+     +---------+     +-----^----+            |
|        |                                |                  |
|        |         +-----------+          |                  |
|        +-------->|   过期   |----------+                  |
|                  | (已终止) |                             |
|                  +-----------+                             |
|                                                            |
|   核心线程池: 始终存活, 不会被回收                          |
|   动态线程池: 按需创建, 空闲超时后终止                      |
|                                                            |
+------------------------------------------------------------+
```

### 2.2 伸缩策略

| 参数 | 默认值 | 描述 |
|------|--------|------|
| `core_threads` | `hardware_concurrency - 1` | 核心线程数(最小保证) |
| `max_threads` | `core_threads * 2` | 最大线程数 |
| `idle_timeout` | 60 秒 | 动态线程空闲超时回收时间 |
| `growth_factor` | 0.5 | 扩展时增加当前线程数的 50% |
| `shrink_factor` | 0.7 | 收缩时保留当前线程数的 70% |

**伸缩触发条件:**
- **扩展**: 队列积压数 > 线程数 x min_tasks_per_thread(默认 10)
- **收缩**: 活跃线程数 < 总线程数 x 0.3, 且持续一段时间

## 3. 任务系统

### 3.1 任务状态机

```
                     +---------+
          submit()   |  待处理 |<------------------+
             ------>| pending |                   |
                     +----+----+                   |
                          | 出队                   |
                          v                        |
                     +---------+                   |
             cancel()|  排队中 |                   |
             <-------| queued  |-------+           |
                     +----+----+       |           |
                          |            |           |
                          v            |           |
                     +---------+       |           |
                     |  运行中 |-------+           |
                     | running |                   |
                     +----+----+                   |
               +---------+---------+              |
               v         v         v              |
         +---------+ +---------+ +---------+      |
         | 已完成  | | 已取消  | |  失败   |      |
         |completed| | canceled| | failed  |      |
         +---------+ +---------+ +---------+      |
               |                                  |
               +----------------------------------+
                           reset()
```

### 3.2 任务优先级

| 优先级 | 值 | 使用场景 |
|--------|-----|----------|
| `critical` | 3 | 系统关键操作(紧急处理/信号响应) |
| `high` | 2 | 高优先级(交互响应/实时数据) |
| `normal` | 1 | 普通优先级(默认, 标准业务逻辑) |
| `low` | 0 | 低优先级(后台同步/日志写入) |
| `background` | -1 | 后台任务(非关键批处理) |

### 3.3 任务接口

```cpp
class task_base {
public:
    virtual ~task_base() = default;
    virtual void execute() = 0;
    virtual void cancel() = 0;

    // 状态查询
    task_state state() const noexcept;
    bool is_canceled() const noexcept;
    bool is_completed() const noexcept;

    // 时间信息
    auto created_time() const;      // 任务创建时间
    auto started_time() const;      // 任务开始执行时间
    auto completed_time() const;    // 任务完成时间

    // 回调
    void set_completion_callback(std::function<void(task_state)> cb);
};
```

### 3.4 高级任务特性

| 特性 | 描述 |
|------|------|
| **取消** | 任务执行前可取消; 运行中任务通过检查点取消 |
| **延迟** | 支持延迟指定时间后执行 |
| **超时** | 任务执行超时后自动取消 |
| **批量提交** | 高效批量提交多个任务 |
| **回调** | 执行前/执行后钩子函数 |
| **亲和性** | 可选绑定特定线程/核心(缓存敏感型任务) |

## 4. 队列架构

### 4.1 多级队列设计

```
+---------------------------------------------------------+
|                      任务提交路径                        |
+---------------------------------------------------------+
|                                                         |
|   任务 --> [优先级判断] --> +----------------------+     |
|                            |   全局优先级队列     |     |
|   本地推送(所有者) ------->|                      |     |
|                            +----------+-----------+     |
|                                       |                 |
|                                       v                 |
|                            +----------------------+     |
|                            |   每线程本地         |     |
|   远程窃取 <---------------|   工作窃取队列       |     |
|                            |                      |     |
|                            +----------------------+     |
|                                                         |
+---------------------------------------------------------+
```

### 4.2 队列操作对比

| 队列类型 | 推入 | 弹出(所有者) | 窃取(其他线程) | 排序方式 |
|----------|------|-------------|---------------|----------|
| 全局优先级队列 | FIFO | 按优先级 | 不适用 | 优先级 -> 时间 |
| 本地工作窃取队列 | LIFO | LIFO(尾部) | FIFO(头部) | LIFO -> FIFO |

### 4.3 工作窃取算法

```
worker_loop(worker_id):
    while 运行中:
        // 1. 优先从本地队列弹出(LIFO - 缓存友好)
        if task = local_queue[worker_id].pop():
            execute(task)
            continue

        // 2. 其次从全局优先级队列获取
        if task = global_queue.pop():
            execute(task)
            continue

        // 3. 尝试从其他线程窃取(FIFO - 减少竞争)
        if task = steal_from_victim():
            execute(task)
            continue

        // 4. 等待(带超时)
        wait_for_tasks(timeout_ms)
```

**窃取策略:**
1. **随机选择受害者**: 减少多线程同时窃取同一队列的竞争
2. **方向差异**: 窃取从头部(FIFO), 本地弹出从尾部(LIFO)
3. **指数退避**: 连续窃取失败后增加等待间隔

## 5. API 设计

### 5.1 任务提交

| 方法 | 描述 | 返回值 |
|------|------|--------|
| `submit(f, args...)` | 提交任务, 自动推导返回类型 | `std::future<R>` |
| `submit_priority(p, f, args...)` | 提交带优先级的任务 | `std::future<R>` |
| `submit_delayed(delay, f, args...)` | 提交延迟执行的任务 | `std::future<R>` |
| `submit_batch(f, count)` | 批量提交 | `vector<future<R>>` |
| `detach(f, args...)` | 分离任务(提交即忘) | `void` |

### 5.2 任务控制

| 方法 | 描述 |
|------|------|
| `wait()` | 等待所有任务完成 |
| `wait_for(timeout)` | 带超时等待, 返回是否成功 |
| `cancel_pending()` | 取消所有排队中的任务 |
| `pause()` | 暂停任务处理 |
| `resume()` | 恢复任务处理 |

### 5.3 线程控制

| 方法 | 描述 |
|------|------|
| `set_thread_count(n)` | 请求调整线程数 |
| `thread_count()` | 获取当前线程数 |
| `enable_scaling(flag)` | 启用/禁用动态伸缩 |

### 5.4 运行时统计

| 字段 | 描述 |
|------|------|
| `stats().tasks_submitted` | 已提交任务总数 |
| `stats().tasks_completed` | 已完成任务总数 |
| `stats().tasks_pending` | 当前排队任务数 |
| `stats().peak_queue_size` | 队列峰值大小 |
| `stats().avg_wait_time_ms` | 平均任务等待时间(毫秒) |

## 6. 配置结构

```cpp
struct config {
    // 线程设置
    size_t core_threads          = hardware_concurrency - 1;  // 核心线程数
    size_t max_threads          = core_threads * 2;           // 最大线程数

    float shrink_factor         = 0.7f;  // 收缩比例
    size_t min_tasks_per_thread = 10;    // 每线程最小任务阈值
};
```

## 7. 使用示例

### 7.1 Web 服务器(混合模式)

```cpp
// 核心线程处理持久连接, 动态线程应对突发流量
thread_pool pool({
    .core_threads = 4,
    .max_threads = 32,
    .enable_priority = true
});

pool.submit_priority(task_priority::high, []() {
    // 处理紧急请求
});
```

### 7.2 批量处理

```cpp
// 批量提交并收集结果
auto futures = pool.submit_batch([](int i) {
    return process_item(i);
}, 1000);

// 等待全部完成
for (auto& f : futures) {
    auto result = f.get();
    // 汇总结果
}
```

### 7.3 延迟任务

```cpp
pool.submit_delayed(100ms, []() {
    // 100 毫秒后执行
});
```

### 7.4 任务取消

```cpp
auto future = pool.submit([]() {
    while (!canceled) {
        // 长时间运行的工作
        if (check_cancelation()) break;
    }
});

pool.cancel_pending();  // 取消所有排队任务
// 或
future.cancel();         // 取消特定任务
```

## 8. 关键设计决策

### 8.1 无锁 vs 互斥锁

| 方案 | 优点 | 缺点 |
|------|------|------|
| **无锁** | 高竞争下性能更好 | 实现复杂, 难以验证正确性 |
| **互斥锁** | 简单可靠 | 高负载下存在竞争 |

**决策**: 本地队列使用细粒度互斥锁; 全局优先级队列使用无锁实现。

### 8.2 工作窃取的优势

1. **缓存友好**: 任务倾向于被创建它的线程执行, 数据局部性好
2. **减少竞争**: 消除单一队列瓶颈
3. **公平性**: 随机窃取顺序防止饥饿

### 8.3 优先级队列实现

- **每优先级独立栈**: 使用 CAS 原子操作
- **老化提升**: 等待过久的低优先级任务自动提升优先级, 防止饥饿
- **批量窃取**: 从繁忙工作者窃取时一次取多个任务, 提高效率

## 11. 线程安全分析

### 11.1 同步原语选型

| 场景 | 推荐原语 | 原因 |
|------|----------|------|
| 全局队列访问 | std::mutex + condition_variable | 简单可靠 |
| 统计计数更新 | std::atomic | 无锁/无争用 |
| 状态标记读写 | std::atomic | 快速读写 |
| 线程数精确计数 | std::atomic + mutex | 需要精确值 |

### 11.2 死锁预防

- 多锁场景按固定顺序获取
- 使用带超时的等待
- 持有锁时禁止调用用户代码

## 12. 性能优化策略

### 12.1 缓存友好

- 本地队列 LIFO 弹出: 利用任务数据局部性
- 可选线程亲和性: 绑定 CPU 核心(复杂, 慎用)

### 12.2 减少竞争

- 工作窃取: 随机选择 victim
- 分段队列: 减少 CAS 争用

### 12.3 自旋 vs 阻塞

| 场景 | 策略 |
|------|------|
| 短等待 | 自旋(std::this_thread::yield) |
| 长等待 | 阻塞(condition_variable) |
